virsh Cheat Sheet

QEMU / KVM · libvirt · qemu-iso-lab — the most used commands at a glance, inherited from kvm-lab
connection: qemu:///system
<VM> = domain name · e.g. debian-server after vmctl export-libvirt
placeholders in orange

≣ Inventory & state

virsh list --all
Every VM (running and off) with its state.
virsh list --state-running
Only the running ones.
virsh domstate <VM>
Single state: running / shut off / paused.
virsh dominfo <VM>
CPU, RAM, autostart, persistence, UUID.
virsh domid <VM> # numeric id (only when running)
virsh domifaddr <VM>
IP addresses (needs the guest agent or a DHCP lease).

⏻ Start & shutdown

virsh start <VM>
Starts the VM.
virsh shutdown <VM>
Orderly shutdown (ACPI). Needs an OS that answers.
virsh reboot <VM>
Orderly reboot.
virsh destroy <VM>
Forced power-off (pulls the plug).
virsh suspend <VM> # pause virsh resume <VM> # resume
virsh autostart <VM> # on at host boot virsh autostart --disable <VM>

▣ Console & screen

virt-viewer <VM> # GUI SPICE/VNC
Graphical window of the VM (virt-viewer package).
virsh console <VM>
Text serial console (leave with Ctrl+]).
virsh screenshot <VM> shot.ppm convert shot.ppm shot.png # ImageMagick
Captures the screen. Convert the .ppm to .png.
virsh send-key <VM> KEY_SPACE # wake up virsh send-key <VM> KEY_ESC
Keys to the guest: handy to leave the screensaver before a screenshot.
virsh send-key <VM> KEY_LEFTCTRL KEY_LEFTALT KEY_DELETE
Ctrl-Alt-Del to the guest.

◇ Guest agent (in-VM)

virsh qemu-agent-command <VM> \ '{"execute":"guest-ping"}'
Checks that the agent answers (OS booted and ready).
virsh qemu-agent-command <VM> \ '{"execute":"guest-get-osinfo"}'
OS name/version from the guest (handy on Windows).
virsh domtime <VM> --sync
Syncs the guest clock through the agent.
# run a command in a Linux guest guest-exec → path:/bin/sh arg:["-c","..."]
On Windows: path cmd.exe, arg ["/c","..."]. Then guest-exec-status with the pid for the output.

▤ Disks & storage pools

virsh domblklist <VM>
Attached disks/ISOs and their paths.
virsh pool-list --all virsh pool-info <pool> virsh pool-refresh <pool> # after adding files
virsh vol-list <pool> virsh vol-info --pool <pool> <vol>
qemu-img info disco.qcow2 qemu-img create -f qcow2 -o preallocation=off new.qcow2 20G
virt-cat -a disco.qcow2 /var/log/syslog
Reads files inside the disk with the VM off (libguestfs) — great to diagnose failed installs.

vmctl disks: artifacts/<vm>/disk.qcow2 · NVRAM: artifacts/<vm>/OVMF_VARS.fd · kvm-lab pools: hdd · shared · Linux · Windows · addons

⇄ Network

virsh net-list --all virsh net-info default virsh net-dhcp-leases default
Virtual networks and assigned DHCP leases.
virsh domiflist <VM>
Network interfaces of the VM (model, MAC, bridge).
virsh net-dumpxml lab-lan virsh net-start lab-lan · virsh net-autostart lab-lan
The isolated LAN of the network lab (bridge virbr-lab, host .254), created by vmctl export-libvirt.

⧉ Snapshot

virsh snapshot-create-as <VM> name \ "description"
Creates a snapshot (disk+RAM when running).
virsh snapshot-list <VM> virsh snapshot-revert <VM> name virsh snapshot-delete <VM> name

</> Definition & XML

virsh dumpxml <VM> > vm.xml
Exports the XML configuration.
virsh edit <VM> # edit + validate
virsh define vm.xml # create/update from a file
virsh dominfo <VM> | grep Persistent
Persistent vs transient.

⚠ Deleting a VM (safely)

# 1. delete ONLY the main disk virsh vol-delete --pool hdd <nome>.qcow2 # 2. remove the definition (+ NVRAM if UEFI) virsh undefine <VM> --nvram
NEVER virsh undefine --remove-all-storage: it deletes every registered volume, the ISOs in the pools included (Windows, Linux, addons…) → irreversible loss.
vmctl unexport-libvirt <vm> # VM exported by vmctl
Removes the definition, keeps disk and NVRAM in artifacts/. Then vmctl clean <vm> if you want the disk gone too.

✛ Diagnostics

virsh dominfo <VM> virsh domstats <VM> # cpu/mem/blk/net live
virsh domblkerror <VM> # disk I/O errors virsh domblkstat <VM> vda
sudo virsh dommemstat <VM>
Memory statistics (needs balloon/agent).
journalctl -u libvirtd --since today cat /var/log/libvirt/qemu/<VM>.log
Host log of the VM's QEMU process.

⊟ Shared folder (virtiofs)

The VM needs memfd memory backing and the virtiofs filesystem; Windows guests need WinFSP. It is the XML vmctl export-libvirt renders for profiles with shared_dir.
<memoryBacking> <source type='memfd'/> <access mode='shared'/> </memoryBacking> <filesystem type='mount' accessmode='passthrough'> <driver type='virtiofs'/> <source dir='…/storage/shared/'/> <target dir='shared'/> </filesystem>

⌘ vmctl ↔ virsh

vmctl stop <vm> vmctl export-libvirt <vm> [--dry-run] [--replace]
Install and provision on plain QEMU, then hand over to libvirt: XML in artifacts/<vm>/libvirt/, disk by absolute path, never copied.
virsh start <vm> · virt-viewer <vm> virsh domifaddr <vm> → ssh utente@IP
After the export use virsh/virt-manager; the hostfwd port of vmctl shell is gone: SSH to port 22 of the DHCP address.
vmctl lab install · vmctl lab up # network lab vmctl export-libvirt pfsense-lab # creates lab-lan too
On plain QEMU the host enters through the router forwards (127.0.0.1:8080…); on libvirt it sits at 192.168.0.254.
virsh shutdown <vm> # until "shut off" vmctl unexport-libvirt <vm> · vmctl start <vm>
Back to vmctl. Never the same disk running in QEMU and libvirt at once.
